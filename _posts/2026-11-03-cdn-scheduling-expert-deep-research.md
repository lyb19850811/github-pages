CDN 调度专家不是「写缓存配置」的岗位，而是**决定全网流量往哪走**的岗位：把终端用户的一次请求，在几百个边缘节点里，实时、精准、最低成本地调度到「最优」那一个。本文以金山云 CDN 调度岗为优先对象，基于金山云官方（产品页/调度文档/北森招聘门户/DOIT 智能运维报道）、牛客网 69 条金山云面经、字节跳动多 CDN 调度平台 JD、火山引擎 HTTPDNS Cache2.0 原文等一手源，拆解这个岗位的 JD、面经、面试题目，以及近十年 CDN 调度技术演进。

## 一、结论先行

- **金山云的「调度」是一套自有智能 GSLB 体系，四种调度类型：DNS 调度、HTTPDNS、边缘 302 调度、中心 302 调度。** 官方表述「多维度调度策略 + 精准带宽预测，跨运营商、跨地域、最小粒度的实时动态资源调度」——这四句话就是岗位的考核大纲：调度维度、带宽预测、跨网跨域、最小粒度、实时动态，每一条都能展开成一整轮面试。
- **金山云确有「CDN 调度算法工程师」岗位，且方向明示为「运筹优化」。** 北森校招门户列有「26 届校招-CDN 调度算法工程师（运筹优化方向）」，说明金山云把 CDN 调度归为**运筹学/优化问题**（带宽约束下的流量分配、成本最小化、质量约束），而非纯工程 CRUD。这是区别于普通后端岗的本质定位。
- **金山云无公开的「调度专家」社招面经，但同公司面经有 69 条可读。** 其中售后工程师（31 题网络排查）、CDN 运维实习（k8s/DNS/TCP）、研发实习生（网络/HTTP/MySQL/Redis）、运维（Linux/nginx/ES/prometheus）四条面经最接近调度岗的知识面。调度岗面试题需以「同公司网络/运维面经 + 业界 CDN 通用考点」外推。
- **竞品 JD 给出岗位能力模型的完整拼图。** 字节跳动「Multi-Cloud CDN Scheduling Platform Engineer」JD 全文可读，要求 Go/Python/Java/C/C++ 至少一种 + HTTP/DNS/TCP-IP/负载均衡/缓存/流量路由/Linux，职责是「多 CDN 调度平台开发 + 自建/商业 CDN 间流量优化 + 成本优化 + 指标监控」。这套要求与金山云调度岗高度同构。
- **面试题目收敛为六类**：调度（DNS vs 302、GSLB 就近接入、Anycast）、缓存（LRU/LFU、热点探测、分层、一致性哈希）、网络协议（HTTP 缓存语义、TCP 拥塞、QUIC、epoll）、回源（回源合并、Range 回源、源站保护）、观测（命中率/首字节/卡顿率口径）、系统设计（链路题/直播热点题/命中率骤降排障题）。
- **近十年调度技术演进是一条「精度提升」主线**：2015 融合 CDN（网络/业务/用户感知）→ 2017 大数据智能运维 → 2018 HTTPDNS/SDNS → 2019 Anycast+GSLB 传播 → 2020 5G MEC 边缘调度 → 2024 MEC-CDN 融合 + **网段级精准调度**（火山 Cache2.0 把调度不准率从万分之六压到万分之二）。

## 二、岗位认识：CDN 调度专家做什么

### 2.1 金山云 CDN 调度体系（一手解剖）

金山云官方把 CDN 的调度能力拆成两层，这是理解岗位的最短路径：

| 能力 | 官方表述 | 考核映射 |
|---|---|---|
| 智能调度 | 多维度调度策略，配合精准的带宽预测，实现跨运营商、跨地域、最小粒度的实时动态资源调度 | 调度策略设计、带宽预测模型、跨网调度、最小调度粒度、实时性 |
| 精准调度 | 自有智能 GSLB 调度体系 + DNS 解析、中央 302 调度、边缘 302 调度、Httpdns 服务 | 四种调度手段的机制与选型 |
| 优质资源 | 电信、联通、移动、中信、广电全覆盖，北上广深大量优质资源 | 节点资源与运营商线路认知 |
| 云监控 | 覆盖全球各运营商监控节点，实时把握服务质量 | 服务质量监控与告警 |
| 大数据分析 | 全链路实时日志采集、分析，链路实时优化 | 日志链路、实时分析、链路优化 |

四种调度类型（金山云官方文档）：

- **DNS 调度**：通过权威 DNS 按用户 LocalDNS 出口 IP 归属返回节点 IP，是最基础的全局调度。缺点：LocalDNS 出口与用户真实位置可能不一致（调度污染）。
- **HTTPDNS**：客户端直接走 HTTP 接口拿解析结果，绕过 LocalDNS，用真实客户端 IP 做精准调度，常用于移动端/App。
- **边缘 302 调度**：边缘节点收到请求后，以 302 重定向到更优节点，在边缘侧二次决策。
- **中心 302 调度**：中心调度系统统一决策后 302 到目标节点，调度决策集中。

这四种的演进逻辑就是「越靠近用户/越集中决策，调度精度越高」——DNS 调度粒度最粗（受 LocalDNS 限制），HTTPDNS 和 302 调度粒度更细、更实时。**面试里能把「为什么需要 HTTPDNS 而不是只靠 DNS」「边缘 302 vs 中心 302 的取舍」讲清，就赢了一半。**

金山云 CDN 的产品迭代时间线（一手）也值得记：**2015-09-26 CDN 控制台 V1.0 上线** → 2016-09 OpenAPI → 2016-11 控制台 V2.0 → 2018-06 大文件下载 → 2018-12 图片小文件。金山云做 CDN 起于 2015 年，但 2021 年 Q4 起主动收缩低毛利 CDN 业务、向智算云转型（36 氪/界面新闻财报报道）——**这是面谈时需要知道的公司背景**：CDN 在金山云已不是增长主轴，但调度技术沉淀仍在。

### 2.2 金山云的调度技术栈（智能运维视角）

DOIT 2017 年报道（金山云大数据技术总监徐寅斐在 GOPS 全球运维大会的演讲）是理解金山云 CDN 调度/运维团队技术栈的关键一手源：

- **数据量**：金山视频云 CDN 服务端**天级日志量近千亿条、数据量近百 T**——调度系统面对的是海量实时数据。
- **平台**：Hadoop + Spark 生态，Kafka 传输，实时流 + 离线流修补架构，边缘计算降低中心压力。
- **存储**：ElasticSearch + Kibana（灵活查询）、Druid（写量大）、HDFS 列存（全量原始日志 ETL）。
- **鹰眼平台**：50+ 业务指标、5+ 维度（域名/区域运营商/链路/缓存状态等）的服务质量查询，满足 80% 日常运维调优需求。
- **自动化**：调度、故障处理、质量调优已实现自动化；下一步探索机器学习/AI 智能化。

**这段信息对应面试画像**：金山云 CDN 调度岗会考察「海量日志实时处理（Kafka/Spark/Flink）、指标口径与聚合（命中率/带宽/卡顿率）、调度与故障的自动化闭环、ML/AI 在调度预测里的应用（带宽预测、热点预测）」。运筹优化方向的 JD 也印证：带宽预测 + 流量分配本质是**带约束的优化问题**。

## 三、金山云面试经验与题目（一手面经）

### 3.1 面经全景

牛客网金山云企业页当前口径：**69 条面经 / 42 个职位 / 题库 0**。岗位覆盖前端、后端、运维、售后、算法、大数据、AI 应用等；**没有公开的「CDN 调度」方向社招/校招面经**，这是本文必须说明的缺口（见附录限制）。可迁移的最近邻面经是：售后工程师、CDN 运维实习、研发实习生、运维。

金山云面试风格（从多条面经归纳）：一般 2~3 轮，一面八股 + 项目，二面深挖简历项目 + 场景题，有手撕算法但难度不高（LRU、哈希表、栈最小值 O(1)、链表 AddNode）；面试官偏「要点式回答」，答太冗长反被打断（一面经原话「话太多了，只要答要点就行了」）。

## 四、其它 CDN 厂商调度专家 JD 与面试

### 4.1 字节跳动「Multi-Cloud CDN Scheduling Platform Engineer」（JD 全文）

这是目前能读到的最完整的「CDN 调度工程师」JD，直接对标金山云调度岗：

- **最低要求**：CS/软工/电子工程/**应用数学**/统计硕士；Go/Python/Java/C/C++ 至少一种；数据结构、OS、网络、数据库基础；了解 HTTP、DNS、TCP/IP、负载均衡、缓存、流量路由、Linux；分析思维 + 对大规模流量系统感兴趣。
- **职责**：参与全球多 CDN 调度平台开发优化；在自建 CDN 与商业 CDN 厂商之间构建流量优化机制（性能/可靠性/成本）；自建 CDN 与多 CDN 流量成本优化；建设资源消耗/回源流量/带宽/缓存效率/服务质量/成本优化相关的指标、监控、分析工具；流量分析、性能优化、排障、调度稳定性与流量效率持续改进。
- **加分**：后端/网络/CDN/流量调度/负载均衡/分布式经验；数据分析/指标系统/监控/优化/自动化；SQL、Python 分析、可视化、时序指标。

**两个关键信号**：①「应用数学/统计」进最低要求 + 金山云「运筹优化方向」，共同印证**调度岗是算法/优化 + 工程双修岗**；②「自建 + 商业 CDN 多源流量优化」说明头部厂商的调度已从「单 CDN 内部调度」升级为「多 CDN 融合调度」——这是行业最新趋势，面试必考。

### 4.2 其它厂商岗位

- **阿里云「算法工程师-运筹优化」**（杭州/上海）：独立设运筹优化算法岗，与 CDN/供应链/物流等资源调度场景对应。

### 4.3 面试题目全景（分维度）

综合心动简历《CDN 与边缘计算校招拆解》、TechPrep《57 CDN Interview Questions》、JavaGuide《CDN 工作原理》：

**（1）调度类**
- DNS 调度和 302 调度的差异？各自优劣与适用场景？
- GSLB 如何实现就近接入？决策输入有哪些（用户 IP、节点负载、性能、响应时间、带宽）？
- 什么是 Anycast？和 DNS 调度的区别？
- HTTPDNS 为什么能比 DNS 调度更准？ECS（RFC 7871）解决了什么？
- 边缘 302 和中心 302 调度怎么选？
- 一致性哈希在调度/缓存里怎么用？节点增删时影响范围？

**（2）缓存类**
- LRU / LFU 及其变种？热点内容如何探测与保护？
- 缓存分层（边缘/区域/中心）怎么设计？回源链路？
- Cache-Control / ETag / Vary 语义；s-maxage 和 max-age 区别？
- 命中率突然下降怎么排查（缓存规则变更、URL 随机参数、全量刷新、源站响应头）？

**（3）网络协议类**
- TCP 拥塞控制演进；QUIC 的连接迁移；epoll 事件驱动；零拷贝；连接复用。
- HTTPS 握手与加速（会话复用、OCSP Stapling、False Start、HTTP/2、QUIC）。

**（4）回源类**
- 回源合并（collapse 请求）怎么实现？Range 回源？源站保护（熔断/限流/隔离）？

**（5）观测类**
- 命中率、回源率、首字节时间、卡顿率的口径怎么定？p50/p95/p99 为什么比均值重要？

**（6）系统设计/场景题（三大必考）**
- **链路题**：用户敲下 URL 到视频首帧播放，逐跳讲出 CDN 参与的环节。
- **设计题**：直播场景突发热点，调度层与缓存层各自怎么扛？
- **排障题**：某区域命中率骤降，给出排查顺序与验证手段。

| 2026 | 多 CDN 融合调度平台成为头部厂商岗位主线（自建+商业 CDN 流量优化） | 字节 JD |

### 5.2 演进主线：一条「调度精度」曲线

**调度精度是这个行业的北极星指标**，十年演进都在做一件事——把「一个请求该去哪个节点」决策得越来越准、越来越细：

- **手段升级**：DNS（受 LocalDNS 限制，粒度粗）→ HTTPDNS（绕过 LocalDNS，用真实客户端 IP）→ 302 调度（边缘/中心二次决策，更实时）→ **网段级调度**（把缓存/调度粒度从「城市-运营商」细化到「/24 网段」）。
- **数据驱动**：从人工规则 → 大数据平台（Kafka/Spark）→ 实时链路 → **带宽预测 + ML/AI**（金山云「精准带宽预测」、火山「网段自适应划分算法」）。
- **架构升级**：单 CDN 内部调度 → 融合 CDN（多厂商资源整合）→ **多 CDN 调度平台**（自建 + 商业 CDN 统一调度 + 成本优化）→ 边缘计算/5G MEC（调度下沉到更近用户的位置）。

### 5.3 一个值得背下来的最新案例：火山 HTTPDNS Cache2.0

火山引擎这篇原文把「调度精准度」问题讲透了，是面试「谈调度粒度」的最佳素材：

- **问题**：业界主流 HTTPDNS 缓存粒度是「城市-运营商」，当自身 IP 库与权威 DNS 不一致时发生「城市级缓存污染」，影响整个城市同运营商用户。
- **业界方案对比**：某国内厂商「省份-运营商」（缓存百条、命中高但精度粗）；火山 Cache1.0「城市-运营商」；海外某厂商「按 ECS(RFC 7871) scope prefix length 动态确定」；火山 Cache2.0「**自研网段库 + 动态适配**」——不依赖权威 DNS 的 ECS 实现也能做到 /24 级粒度。
- **工程实现**：两级一致性哈希（源 IP+域名 → 缓存层；域名+网段 → 递归层）；缓存三级（网段/城市-运营商/全局）；主动+被动刷新分级；缓存预取（亲缘网段批量预热）。
- **收益**：调度不准率**万分之六 → 万分之二（降 60%）**；缓存命中率 +15%；缓存量/CPU/出网流量降约 70%。

**这道题的面试价值**：它把「调度精度 vs 缓存命中率 vs 存储成本」的三角权衡、ECS 协议、一致性哈希、缓存污染、自适应网段划分全部串起来了，是调度岗系统设计题的完美答案模板。

## 六、准备建议与红线

### 6.1 复习路线（按优先级）

1. **HTTP 缓存语义 + DNS 解析链路**（必考基础）：Cache-Control/ETag/Vary、DNS 递归/迭代、CNAME 到 GSLB 的完整流程。
2. **GSLB 调度体系**：DNS/HTTPDNS/302 四种调度手段的机制、精度、适用场景；Anycast；ECS。
3. **缓存与分布式**：LRU/LFU 变种、一致性哈希、缓存分层、热点探测、回源策略。
4. **Linux 网络栈 + 传输协议**：epoll、零拷贝、连接复用、TCP 拥塞控制、QUIC。
5. **运筹优化（针对金山云方向）**：带宽约束下的流量分配、成本最小化、线性/整数规划、启发式算法、在线预测（带宽预测/热点预测）——这是金山云「运筹优化方向」的差异化考点。
6. **大数据与观测**：Kafka/Spark 实时链路、命中率/带宽/成本/卡顿率指标口径、SQL/Python 分析。
7. **动手验证**：用 Nginx 搭带缓存的反向代理，抓包观察缓存命中/回源；写一个最小的一致性哈希 + LRU。

### 6.2 高频题清单（背到能口述）

- 用户输入 URL 到页面渲染，CDN 参与哪些环节（逐跳）。
- DNS 调度 vs HTTPDNS vs 302 调度的差异与选型。
- 直播突发热点：调度层 + 缓存层各自怎么扛。
- 某区域命中率骤降：排查顺序。
- 一致性哈希如何减小节点增删影响；LRU/LFU 区别。
- Cache-Control 各指令含义；s-maxage 与 max-age 区别。
- TCP 三次握手四次挥手、QUIC、epoll、零拷贝。

### 6.3 红线（易踩坑）

- **把 CDN 调度当「负载均衡」单点讲**：调度是「全局 + 多手段 + 数据驱动」，不只是轮询/加权。要落到「GSLB + 四种调度类型 + 带宽预测」。
- **只背八股、不讲精度权衡**：面试官考的是「调度粒度 vs 命中率 vs 成本」的取舍，火山 Cache2.0 案例是最好的素材。
- **忽略公司背景**：金山云 2021 起主动收缩低毛利 CDN 业务、转向智算云——面谈时对「CDN 战略定位」要有认知，不要把 CDN 讲成金山云当前的绝对主轴。
- **忽略运筹优化**：金山云岗位方向明示「运筹优化」，纯工程准备会漏掉差异化考点（带宽约束优化、成本最小化）。
