检索增强生成（Retrieval-Augmented Generation, RAG）是企业落地大模型最主流的方案。本文拆解其流程、瓶颈与进阶方向。

## 一、是什么

模型训练数据有截止时间、也会"记错"。RAG 的思路是：**先检索外部知识库的相关内容，再把检索结果连同问题一起喂给模型生成**。

标准流程：

```
用户提问 → 向量化查询 → 向量库检索 Top-K → 重排序(Rerank)
        → 拼装上下文 → 送入 LLM → 生成答案（带引用出处）
```

## 二、为什么重要

- 突破训练数据的时间截止限制（可用实时数据）
- 可接入企业私有知识，且**数据不出内网**
- 能给出引用出处，可溯源、可审计
- 改造成本远低于微调，是企业落地最主流的方案

## 三、核心组件

| 组件 | 作用 | 关键点 |
|---|---|---|
| 文档切分 | 把长文档切成 chunk | 切分粒度、重叠、语义边界 |
| Embedding | 文本转向量 | 模型选型、维度 |
| 向量库 | 存储与检索 | Milvus / FAISS / pgvector |
| Rerank | 二次精排 | 交叉编码器提升精度 |
| 混合检索 | BM25 + 向量 | 兼顾关键词与语义 |

## 四、关键认知：瓶颈在检索，不在 LLM

RAG 的效果瓶颈往往**不在生成模型，而在检索质量**——检索不到、检索不准，再强的 LLM 也只能"无米之炊"。

- 切分策略：按语义切分优于按固定长度
- Embedding 质量：领域相关的 Embedding 模型效果更好
- Rerank 是性价比很高的精度提升手段
- 混合检索（BM25 + 向量）能兼顾精确匹配与语义召回

## 五、进阶方向

- **GraphRAG**：用知识图谱增强多跳推理与实体关系
- **Agentic RAG**：让 Agent 自主决定检索策略、检索次数、检索范围
- **长上下文 RAG**：窗口扩大后，RAG 与长上下文的边界在变化，但"精准检索"依然有价值

## 六、与微调的分工

RAG 解决"知识"，微调解决"行为/风格/格式"。二者不是二选一，可组合使用。

**一句话总结**：RAG 的本质是"给模型外接一个可溯源的记忆"，它的上限取决于检索系统的质量，而非生成模型本身。
