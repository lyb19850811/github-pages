上下文窗口（Context Window）决定模型一次能"记住"多少信息。本文梳理演进、问题与工程原则。

## 一、是什么

模型单次推理能"看到"并处理的 token 总量上限，包含输入 + 输出。

## 二、演进

```
GPT-3: 2K → GPT-3.5: 4K/16K → GPT-4: 8K/32K/128K
→ Claude: 200K → Gemini: 1M+ → 国产模型: 128K~1M
```

## 三、核心问题

### 3.1 大海捞针（Lost in the Middle）
窗口大了，但模型对中间部分的注意力会衰减——关键信息放在开头或结尾更容易被"记住"，中间容易被忽略。

### 3.2 成本陷阱
长上下文的 API 调用非常贵，成本随长度线性/超线性增长。盲目塞满窗口既不省钱、效果也未必更好。

## 四、上下文工程原则

不是塞得越多越好，而是**如何塞进最相关的信息**：

1. 相关性优先：用检索/重排挑出最相关的内容
2. 结构化组织：重要的放两端，中间放次要信息
3. 动态裁剪：Agent 多轮对话中主动压缩、遗忘无关历史

**一句话总结**：上下文窗口是"注意力的带宽"，上下文工程的核心是把有限的带宽分配给最相关的信息。
