智能体（Agent）让模型从"回答问题"升级为"完成任务"。本文拆解其能力栈、核心难点与工程化路径。

## 一、是什么

Agent 让模型能**自主规划目标 → 分解步骤 → 调用工具 → 观察结果 → 迭代修正**，形成闭环。

## 二、核心能力栈

| 能力 | 说明 |
|---|---|
| 规划 Planning | 把复杂目标拆成可执行的步骤序列 |
| 工具调用 Tool Use | 搜索、读写文件、执行代码、调用 API、操作浏览器 |
| 记忆 Memory | 短期（上下文）+ 长期（向量库/数据库） |
| 反思 Reflection | 检查自身输出，发现错误后重试 |

## 三、为什么重要

从"问答机器"升级为"数字员工"，是当前最热的工程方向。各类 AI 编程助手、AI 办公工作台、自动化流程本质上都是 Agent 化。

## 四、核心难点：可靠性

Agent 最大的难题是**可靠性**——多步骤任务容易半途跑偏，错误会累积放大。

- 单步正确率 95% 的任务，10 步后正确率只有 $0.95^{10} \approx 60\%$
- 错误会通过"工具调用的副作用"扩散（写错文件、发错消息）

## 五、工程要点

1. **上下文工程**：在有限的窗口里塞进最相关的信息，是 Agent 成败的关键
2. **边界与兜底**：高风险操作（删除、付款、外发）必须人工确认
3. **可观测性**：记录每一步的输入输出，方便定位"哪一步跑偏"
4. **任务粒度**：把大任务拆成可验证的小任务，降低失败影响面

## 六、趋势

- 多 Agent 协作（编排、分工、评审）
- 与 RAG、工具生态深度结合
- 从"通用 Agent"走向"垂直场景 Agent"（客服、运维、编程）

**一句话总结**：Agent 的价值在于"闭环完成任务"，它的瓶颈不在"能力上限"而在"可靠下限"——把跑偏的概率管住，比把能力做大更重要。
